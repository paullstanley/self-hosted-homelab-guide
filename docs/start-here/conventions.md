# Conventions: example values and how to use your own

Every page uses the same made-up names and addresses, so that commands on different pages agree with each other. Nothing here is a real network. Before you run anything, replace these values with yours.

## Choosing your own values

- **Subnet.** Any private range works. Avoid `192.168.0.0/24` and `192.168.1.0/24` if you will ever reach home over a VPN from another network, because those are the ranges most other networks use and the two would clash.
- **Local domain.** Use a subdomain of a domain you own, such as `home.<your-domain>`. Do not invent a top-level name, and do not use `.local`: that name belongs to mDNS (Bonjour), and using it for ordinary DNS breaks discovery on Apple devices.
- **IPv6 prefix.** Generate your own random ULA prefix rather than copying the example. [Local-only IPv6](../network/local-only-ipv6.md) explains how and why.
- **Host names.** Lower case, letters, digits and hyphens only. Kubernetes lower-cases node names; a host name with capitals leads to two spellings of the same machine.
- **Addresses for servers.** Give cluster machines addresses below the DHCP pool and set them on the machine itself, not only as a router reservation.

## Replacing the examples in the files

The files in [`files/`](../../files/) contain the same examples. After cloning, list where each one appears before you change it:

**Run on: your computer**, in the root of the repo.

```sh
grep -rn "192.168.50\." files | wc -l
grep -rn "home.example.com" files | wc -l
grep -rn "fd00:1234:5678" files | wc -l
grep -rn "192.168.101\." files | wc -l
grep -rn "/Volumes/Media" files | wc -l
```

Then replace them. This example changes the domain everywhere under `files/`; do the same for each value that differs. On macOS, `sed -i` needs an empty argument as shown; on Linux, leave out the `''`.

```sh
grep -rl "home.example.com" files | xargs sed -i '' 's/home\.example\.com/home.mydomain.net/g'
```

> **Pitfall:** replace the most specific value first. Changing `192.168.50.` before `192.168.50.11` is fine, but a careless pattern such as `192.168.5` also matches `192.168.50.` and `192.168.5.`. Check the result with `git diff` before you use any file.

> **Pitfall:** the scripts for the router and the access point keep their values in a short block at the top (`THE SPEC` in `xt8-bootstrap.sh`, the variables at the top of `a7-ap-setup.sh`). Change them there, or pass them as environment variables where the page says you can, rather than editing lines further down. The media scripts work the same way: [`media-health.sh`](../../files/media/media-health.sh) takes `QBIT_HOST`, `VOLUMES`, `DOWNLOADS` and the app URLs as environment variables, and [`qbit-check.ps1`](../../files/media/qbit-check.ps1) takes `-VpnAdapter`, `-SavePath` and `-MediaServer` as parameters.

## How commands are shown

- A line such as **Run on: server-1** above a block says which machine to paste it into. "Your computer" means the laptop or desktop you are working from.
- Commands that name a path under `files/` are run from the root of your clone of this repository.
- Commands start at the left margin and can be pasted whole.
- `sudo kubectl` is written out because k3s's own `kubectl` reads a root-only config file by default.
